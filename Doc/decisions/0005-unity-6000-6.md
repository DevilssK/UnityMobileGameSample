# 0005 — Unity 6000.6.7f1 et SDK associés

Date : 2026-10-24 · Statut : acceptée

## Problème
Le sample visait Unity `6000.1.7f1`, non installé localement et hors support. Le propriétaire a choisi de passer à la dernière version disponible, `6000.6.7f1`, et a ouvert le projet avec, ce qui a mis à jour les packages (mode `updateDependencies`).

## Décision
- Éditeur : `6000.6.7f1`.
- Packages : versions résolues par l'éditeur à l'ouverture, plus Unity IAP `5.4.4` (au lieu de la `4.15.0` proposée), LevelPlay `9.5.1` et Leaderboards `2.3.4` (la `2.3.3` ne compile pas en 6000.4 et plus). Détail dans `Doc/dependencies.md`.
- Le code client est seulement adapté pour compiler (API LevelPlay 9, `StoreSpecificIds` d'IAP 5). `StoreClient` garde l'ancienne API d'IAP, encore fournie par la 5.x mais marquée obsolète, jusqu'à sa réécriture (décision 0003).

## Alternatives écartées
- Unity 6.3 LTS (`6000.3.26f1`, installé, supporté jusqu'en décembre 2027) : fenêtre de support plus longue et plus prévisible ; écartée par choix du propriétaire.

## Conséquences
- Selon les sources consultées (non officielles), Unity 6.6 n'est pas une version LTS : prévoir une montée vers la prochaine LTS avant une sortie en production. Au 2026-10-25, Unity 6.7 est en bêta ; Cloud Code 3.0 (modules .NET 10, Stateful Cloud Code) exige 6000.7. Rester sur le chemin Cloud Code 2.10.4 (.NET ≤ 9) jusqu'à une 6.7 stable (arbitrage A5 du diagnostic du 2026-10-25).
- La compatibilité des adaptateurs réseaux LevelPlay, d'Android (minSdk/targetSdk) et d'iOS/Xcode avec cette version reste à vérifier par un build.
- Avertissements à traiter plus tard : API IAP obsolètes dans `StoreClient`, directive `DEVELOPMENT_BUILD` dépréciée (UAC0009).
